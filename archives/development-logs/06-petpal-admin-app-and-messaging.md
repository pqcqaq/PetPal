# Archive 06: Root Admin, App Rebuild And Messaging

Covered sections: 88-104

## Scope

本卷记录最近一轮以“真实可用”作为目标的收口阶段，重点包括根级后台接管、默认落点统一、App 双工作台重构、健康档案与资质材料补齐，以及订单消息闭环。

## Main Outcomes

- App 端“我的”页与账户能力视图继续去模板化，统一为 PetPal 账户和后台能力表达。
- Web 公开辅助页、登录页、404 页与默认标题继续清理模板语言，统一成 PetPal 后台语义。
- 根级后台首页升级为治理摘要页，并逐步支持：
  - URL 预设过滤直达
  - 前移值班动作
  - 首页接手紧急投诉
- 根级后台路由入口逐步脱离旧 `console` 目录，回调审计、告警队列、照料者审核、投诉工单的真实实现先后迁入 `pages/petpal-admin/*`。
- 登录完成、路由守卫、实时权限同步与“返回总览”全部统一为 `/petpal-admin` 默认落点逻辑。
- App `PetPal` 页面重构为主人工作台 + 照料者工作台，订单详情页补齐完成确认、评价、投诉等动作。
- 宠物健康档案轻量字段、照料者资质材料上传和“无材料不得审批通过”的后台审核规则落地。
- 订单消息闭环上线：
  - 后端新增订单会话与消息模型。
  - 主人和照料者可在订单详情页发送文字和附件。
  - Web/App 工作台可直接看到最近消息摘要和未读计数。

## Resulting Baseline

- 根级 PetPal 后台已经具备独立存在的结构，不再只是旧控制台页面的外壳。
- App 端已经从“业务信息展示页”进入“可执行主要动作的真实工作台”阶段。
- 最近一轮把健康档案、资质材料和订单消息补齐后，PetPal 主链路的业务真实感显著增强。
